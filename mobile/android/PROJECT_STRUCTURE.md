# Android Project Structure

This directory contains the native Android companion app. It is a single Gradle
project with one `app` module, two install flavors, and a native USB firmware
flasher built with CMake.

```text
mobile/android/
├── settings.gradle                 # Project name, app module, plugin/dependency repositories
├── build.gradle                    # Android Gradle Plugin and Kotlin plugin versions
├── gradle.properties               # Gradle JVM and AndroidX settings
├── build_apk.ps1                   # Builds and publishes both debug APK flavors
├── local.properties                # Machine-local Android SDK path, generated by build script
├── backups/                        # Local APK/backup copies; not application source
└── app/
    ├── build.gradle                # Android app, dependencies, flavors, SDK and native build
    └── src/
        └── main/
            ├── AndroidManifest.xml # Permissions, activities and flavor-provided app label
            ├── java/com/espdownload/mobile/
            │   ├── MainActivity.java       # Native screens, host/device API, settings, OTG flasher UI
            │   └── QrCaptureActivity.java  # CameraX and ML Kit QR capture
            ├── res/
            │   └── drawable/        # App vector/drawable resources
            └── cpp/
                ├── CMakeLists.txt   # Builds the native ESP serial flasher library
                ├── android_port.c
                ├── android_port.h
                ├── flasher_jni.c    # JNI bridge used by the Java flasher UI
                ├── *-LICENSE        # Native component license notices
                └── esp-serial-flasher/ # Embedded Espressif serial-flasher source
```

The Host & Telegram screen edits the complete GPIO command definition, including
command name, trigger text, board-supported pin, pulse polarity/duration, and
Telegram reply. Settings are saved through the local host and synchronized with
the ESP32; dashboard jobs and Telegram URL logs use the ESP32's shared API, so
changes made in the Android app are reflected in the Host dashboard and vice
versa.

## Build configuration

- `app/build.gradle` defines the `standard` and `freshTest` product flavors with `versionCode 3` and `versionName "1.3"`.
- `standard` installs as `com.espdownload.mobile`.
- `freshTest` installs side-by-side as `com.espdownload.mobile.fresh`; it starts
  without the normal app's saved host or preferences.
- Both flavors share the same app sources and dependencies. Flavor-specific
  application IDs, labels, and the fresh-install flag are set in Gradle.
- The project uses Java 17, Kotlin JVM 17, Android SDK 36, NDK
  `27.2.12479018`, and CMake `3.22.1`.
- CameraX and ML Kit provide QR capture; `usb-serial-for-android` and the
  embedded Espressif flasher support USB OTG flashing.
- **Offline Mode Support**: Allows admin login with default `admin`/`admin` or cached credentials even when ESP32 or PC Host is offline, guaranteeing immediate access to the OTG firmware flasher in the System Check tab.
- **Multi-target Host Discovery**: Scans subnet for both ESP32 (port 80 `/api/v1/identify`) and Windows PC Host (port 8787 `/api/mobile/health`).
- **Config Synchronization**: Security tab features "Sync Config" button to export timestamped `.espbackup` files to `Download/Esp32 System/` and push configuration to the connected host or ESP32.
- **DuckDNS Remote Access**: Wi-Fi/AP screen provides configuration for DuckDNS domain, token, and status monitoring.

## Build and output

Run `.\build_apk.ps1` in this directory to build both variants.

```text
app/build/outputs/apk/standard/debug/app-standard-debug.apk
app/build/outputs/apk/freshTest/debug/app-freshTest-debug.apk
```

The Node.js server (`local-host/server.mjs`) serves APKs directly from the
Gradle build outputs - no manual copy to `local-host/public/` is needed.

`app/build/`, `.gradle/`, `.kotlin/`, and native `.cxx/` directories are
generated build state, not source. `local.properties` contains the local
Android SDK location and is generated for the current machine. Keep files in
`backups/` private: backup artifacts may contain credentials or device
configuration.
